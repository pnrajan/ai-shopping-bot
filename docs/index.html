Why it feels fast

The model speaks twice. Everything else is deterministic.

Each stage spends a model call only when a regex, a lookup table, or a cached result cannot answer first. Latency and cost stay flat as conversations get longer.

Understand once, typed

Query, filters, intent, and extras like gift mode or an essentials checklist arrive in one structured response. Nothing downstream re-reads the raw text.

Follow-ups stay in memory

"Which of these are under $300?" filters what the user already saw. Regex handles it. The model only steps in when regex cannot decide.

"X vs Y" becomes a table

Two targeted searches, best match on each side, and a side-by-side comparison in the data payload. No prose to parse.

Any model, per role

OpenAI, SiliconFlow, and OpenRouter behind one client. A small fast model for understanding, a stronger one for the reply. Swap with an env var.

A hard budget per request

Four model calls, maximum. The normal path uses two. Overruns raise an error instead of quietly running up a bill.

Production basics included

SQLite or in-memory sessions. Redis or in-memory cache. API key auth, rate limiting, OpenTelemetry traces, and a Dockerfile.

Prices and stock, tracked

Every product seen becomes an observation. Watch an item and get alerts on price drops, a target price, or stock changes. History per product, re-checks on a schedule.

How it works

Eight stages. Any one can end the turn early.

A request context flows through the stages in order. When a stage has the answer, the rest are skipped. Only persist always runs. Click a stage, or let it play.

Quick start

Clone, run, chat. No keys yet.

A deterministic fake LLM and fake catalog ship in the box. The whole pipeline runs on a laptop before you touch a single API key. Edit the request on the right and copy the curl.

git clone https://github.com/pnrajan/ai-shopping-bot.git
cd ai-shopping-bot
bash scripts/setup.sh   # creates .venv, installs deps, copies .env.example to .env
bash scripts/run.sh     # serves on http://127.0.0.1:8000

Interactive OpenAPI docs are served at http://localhost:8000/docs once the server is running.

Going live

Go live by picking a model per role.

Set SHOPBOT_LLM=live and choose a model for each of the four roles. Model ids are provider/model. Keys are read from the environment only, held as secrets, and never logged.

For a real catalog set SHOPBOT_CATALOG=unwrangle and UNWRANGLE_APIKEY. Set SHOPBOT_API_KEY to require an X-API-Key header.
